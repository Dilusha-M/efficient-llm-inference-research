### Task 2 — Conservative Launch Decision
**Conservative Procedure for Context Size and GPU Layer Offload:**
1.  **Context Size Selection:**
    *   **Strategy:** Start by verifying that the GPU layers fit within the memory footprint of the chosen context size.
    *   **Procedure:**
        1.  Calculate the memory cost of the chosen context size (e.g., 1024 tokens).
        2.  Compare this cost to the available GPU memory (16 GB).
        3.  If the GPU layers fit within the context size's memory footprint, proceed to layer offload.
        4.  If layers exceed available memory, reduce the context size to fit within 16 GB.
    *   **Why:** This prevents launching a model that cannot be executed on the hardware, which is the definition of a "safe" launch.

2.  **GPU Layer Offload Selection:**
    *   **Strategy:** Offload only layers that are actually heavy and necessary for inference.

        1.  Identify layers in the chosen context size that consume the most memory.
        2.  Identify layers in the *same* context size that are lighter.
        3.  **Do not** offload a layer if a lighter layer in that context size is available.
        4.  If all layers in the chosen context size are heavier than those in the target context size, the current context size is optimal for memory efficiency.
    *   **Why:** This maximizes memory efficiency while ensuring the model fits within the available GPU memory.

### Task 5 — User-Visible Latency
**Explanation of Latency Phases:**

1.  **Time to First Token (TFPT):**
    *   This is the time required to read the input prompt and prepare to generate the first token.
    *   Symbolic Equation: $T_{TFPT} = T_{read\_prompt} + T_{pre\_compute}$
    *   Optimization impact: Optimizing prompt processing only reduces the first token latency if the first token is generated from a specific token in the prompt. If the first token is generated from a different token in the prompt, optimizing the prompt only affects the overall latency.

2.  **Prompt-Evaluation Throughput:**
    *   This is the average number of tokens generated per second.
    *   Symbolic Equation: $P_{prompt} = \frac{\text{Total Tokens Generated}}{\text{Prompt Duration}}$

3.  **Decode Throughput:**
    *   This is the number of tokens generated per second during inference.
    *   Symbolic Equation: $P_{decode} = \frac{\text{Total Tokens Generated}}{\text{Inference Duration}}$

4.  **Total Wall-Clock Time:**
    *   The sum of the time to first token and the time to generate all tokens.
    *   Symbolic Equation: $T_{total} = T_{TFPT} + T_{total\_tokens}$

**Example where optimizing prompt processing barely changes the user's experience:**
*   **Scenario:** A user sends a prompt "Hello world" (length 13 tokens) and waits for the model to finish (length 200 tokens).
*   **Optimization:** Optimizing the prompt processing (e.g., adding a special token for the start, optimizing the prompt length slightly, or adding a token at the very beginning of the prompt).
*   **Result:** The user's experience (latency from prompt start to token generation) remains nearly identical because the optimization only affects the *first* token generation, which is very short (1 token) compared to the subsequent generation. The user rarely perceives a change in the duration they *wait*.
