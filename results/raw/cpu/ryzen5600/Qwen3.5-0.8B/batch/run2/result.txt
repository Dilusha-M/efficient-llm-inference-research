## Task 5 — User-Visible Latency
**Difference Explanation**
*   **Time to First Token (TTFT):** The time it takes for the system to start processing the prompt and generating the first token. It is measured from `start_time` to `first_token_time`. It is a **hardware-dependent** measurement.
*   **Prompt-evaluation throughput:** The average number of tokens generated per second (tokens_per_second) during the generation phase. It is a **software-dependent** measurement.
*   **Decode throughput:** The average number of tokens generated per second during the decoding phase. It is a **hardware-dependent** measurement (though often approximated as a fraction of the total throughput).
*   **Total wall-clock time:** The sum of all individual phases. It is a **total** measurement.

**Symbolic Equation for Total Time ($T_{total}$):**
$$T_{total} = T_{ttft} + T_{prompt\_eval} + T_{decode} + T_{finish}$$
Where:
*   $T_{ttft}$ = Time to first token
*   $T_{prompt\_eval}$ = Time to evaluate the prompt (e.g., 0.5s for 2000 tokens)
*   $T_{decode}$ = Time to process and output the generated tokens
*   $T_{finish}$ = Time to finalize the output (e.g., write to file)

**Example where optimizing prompt processing barely changes the experience:**
*   **Scenario:** The model is 8B, generating 200 tokens. The total wall-clock time is 50 seconds.
*   **Optimization:** The prompt processing time is **0.1 seconds**.
*   **Result:** Even if you optimize the prompt processing to **0.05 seconds**, the total time remains **50.1 seconds**. The user's experience is effectively unchanged because the bottleneck is not the prompt processing (which is fast for 200 tokens), but rather the generation phase.
