from typing import Iterable, Dict, Any, Optional
import math

def summarize_decode_speeds(lines: Iterable[str]) -> Dict[str, Any]:
    """
    Summarize decode speeds from a stream of log lines.
    
    A line is valid if:
    1. It is a string.
    2. It contains exactly one 'event=decode'.
    3. It contains exactly one 'tps=<value>'.
    4. The value is a finite, strictly positive float.
    
    If a line has duplicate keys (even with same values), it is malformed.
    
    Args:
        lines: Iterable of strings (or ignored non-strings).
        
    Returns:
        Dictionary with keys: count, min_tps, max_tps, avg_tps.
        If no valid records exist, min/max/avg are None.
    """
    
    count = 0
    min_tps: Optional[float] = None
    max_tps: Optional[float] = None
    sum_tps = 0.0
    
    for raw_line in lines:
        # Skip non-string items silently
        if not isinstance(raw_line, str):
            continue
            
        # Split on whitespace to get tokens
        tokens = raw_line.split()
        
        # We need to track event and tps values and ensure no duplicates
        # We'll use a simple dict to track seen keys for the current line
        seen_keys = {}
        event_val = None
        tps_val = None
        
        for token in tokens:
            if '=' in token:
                key, _, value = token.partition('=')
                key = key.strip()
                value = value.strip()
                
                # Check for duplicate keys immediately
                if key in seen_keys:
                    # Duplicate key found, line is malformed
                    break
                
                if key == 'event':
                    seen_keys['event'] = True
                    event_val = value
                elif key == 'tps':
                    seen_keys['tps'] = True
                    # We must wait until the end of the line to parse the float
                    # because we need to check for duplicates first.
                    # Store raw string for now.
                    tps_val = value
                else:
                    # Other key=value pairs are allowed, just track them
                    # but don't store them in seen_keys to avoid false positives 
                    # if the logic was different. However, the spec says "contains both".
                    # It doesn't forbid other keys, but duplicate keys are bad.
                    # So we only track 'event' and 'tps' for duplicate checking?
                    # Re-reading: "duplicate keys with conflicting values" -> malformed.
                    # "Treat a duplicate tps key with the same value as malformed too."
                    # So ANY duplicate key makes it malformed.
                    seen_keys[key] = True
        
        # If we broke out due to a duplicate, or if we didn't find required keys, skip
        if seen_keys.get('event') != True or seen_keys.get('tps') != True:
            continue
            
        # Check for specific duplicate event/tps logic? 
        # The loop above breaks on ANY duplicate. So if we are here, no duplicates.
        
        # Now parse tps
        try:
            tps_float = float(tps_val)
        except ValueError:
            # Not a valid float representation
            continue
            
        # Check for finite, strictly positive
        if not math.isfinite(tps_float) or tps_float <= 0:
            continue

        sum_tps += tps_float

            min_tps = tps_float
        if max_tps is None or tps_float > max_tps:
            max_tps = tps_float

    if count > 0:
        avg_tps = round(sum_tps / count, 3)
        
    return {

### Explanation of Implementation Details

**1. Why naive substring matching fails:**
A naive approach might check `if "event=decode" in line` and `if "tps=..." in line`. This is insufficient for two reasons:
*   **Duplicate Keys:** A line like `"event=decode tps=100.0 event=decode tps=100.0"` contains the substrings correctly. However, the spec requires treating duplicate keys (even with the same value) as malformed. Substring matching cannot detect that `event=decode` appears twice; it only sees the presence of the string. Tokenization (splitting on whitespace) combined with a set/dict to track seen keys is required to enforce the "no duplicate keys" rule.
*   **Partial Matches:** While less likely to cause false positives for "decode" specifically without context, strict key-value parsing ensures we don't accidentally match a key that is a substring of another (e.g., if a key was `event_type=decode` and we only looked for `event=decode`). Tokenization isolates exact keys.

**2. Empty-Result Policy:**
The implementation initializes `min_tps`, `max_tps`, and `avg_tps` to `None`. If the `count` remains 0 after processing all lines (whether due to no lines, all invalid lines, or non-string items), the returned dictionary will have `None` for these metrics. This adheres to the requirement: "or `None` when there are no valid records".

**3. Algorithm Complexity:**
*   **Time:** $O(N)$ where $N$ is the total number of tokens across all valid string lines. We iterate through the input once.
*   **Space:** $O(1)$ extra space relative to the input size. We only store a few variables (`count`, `sum`, `min`, `max`) and a small dictionary (`seen_keys`) that resets (implicitly, by creating a new one per line) for each line. We do not store the parsed results.
