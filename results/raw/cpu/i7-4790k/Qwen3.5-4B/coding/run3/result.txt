### Explanation of Naive Approaches and Empty-Result Policy

#### Why Naive Substring Matching Fails
Naive substring matching (e.g., `'event=decode' in line` and `'tps=' in line`) is prone to two specific failures in this context:

1.  **Accepting Wrong Events**: 
    A naive check `'event=decode' in line` is susceptible to false positives if the line contains similar substrings elsewhere or if the event value is slightly different (e.g., `event=decode_v2`). More critically, if the format is loose, a line like `event=decode tps=10` might match, but so might `event=decode_extra tps=10` if the check is merely `startswith('event=decode')`. The requirement specifies the event must be exactly `decode`. Proper parsing by splitting on `=` and checking the exact key-value pair ensures `event` equals `decode` precisely.

2.  **Accepting Malformed Duplicates**:
    A naive check might look for `'tps='` once using a simple regex like `re.search(r'tps=\S+', line)`. If a line contains `event=decode tps=10 tps=10`, a single regex match returns `True` (finding the first `tps=`), ignoring the fact that there is a second `tps=` key present. The requirement states that duplicate `tps` keys make the record malformed. A robust solution must parse the line into tokens, count the occurrences of the `tps` key, and ensure the count is exactly 1.

#### Empty-Result Policy
The function returns `None` for `min_tps`, `max_tps`, and `avg_tps` if `count` is 0.
*   **Rationale**: If no valid records are found (e.g., all lines are malformed, empty, or missing the `event=decode` and `tps` fields), there is no data to derive a minimum, maximum, or average from. Returning `None` prevents `ZeroDivisionError` when calculating the average and correctly signals that the dataset yielded no usable inference metrics.
