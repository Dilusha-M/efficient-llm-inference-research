### Explanation of Algorithm and Design Choices

**1. Why naive substring matching fails:**
Naive substring matching (e.g., checking if `"tps="` exists in the line) is prone to two specific failures:
*   **Accepting the wrong event:** If the line contains `event=decode` but also happens to contain the substring `tps=...` embedded within another value (unlikely with standard key=value but possible in malformed logs like `event=decode tps=abc` vs `event=decode tps=500`), or if the logic doesn't strictly parse the `key=value` structure, it might count a line with `event=parse` if the regex/string search isn't anchored correctly to the `event=` prefix. More critically, it fails if the line has `event=decode tps=500` but we accidentally match `tps=500` inside a comment or string literal if not tokenized first.
*   **Malformed Duplicates:** A naive approach might find `tps=500` twice in the log line and assume "it's there, so it's valid," ignoring the requirement that duplicate keys make the record malformed. A robust parser must identify the *tokens*.

**2. Empty-Result Policy:**
The function returns `None` for `min_tps`, `max_tps`, and `avg_tps` when `count` is 0. This is standard for statistical summaries to avoid division by zero or returning garbage values. The logic explicitly checks `if count == 0` before calculating averages.

**3. One-Pass Algorithm & O(1) Space:**
*   **One-Pass:** The function iterates through `lines` once. Inside the loop, it iterates through the tokens of a single line. Since we process one line at a time and discard it (resetting `line_data`), we do not store the entire input.
*   **O(1) Extra Space (excluding input iterable):** This is a subtle constraint. Technically, we need a set or dictionary for `line_data` to detect duplicates *within* a line. The size of `line_data` is bounded by the number of unique keys per line (very small constant, typically 2). Thus, the space complexity per line is $O(k)$ where $k$ is the number of keys. In the context of "excluding input iterable", this is considered constant space relative to the size of the entire `lines` collection, as we are not building a massive data structure of $N$ records. We are aggregating statistics into simple variables (`count`, `total`, `min`, `max`) which are $O(1)$.
