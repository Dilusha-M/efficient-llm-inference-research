2.  **Q4\_K\_M (4.8 GB):** This format requires 4.8 GB of memory for weights. This fits within the 6 GB GPU memory. The remaining memory (6.0 GB - 4.8 GB = 1.2 GB) is available for the KV cache and intermediate activations.

1.  **KV Cache:** The memory needed to store the Key/Value states for the attention mechanism, which scales with the context length (2,000 tokens in this case).

1.  **Inference Latency (Time to First Token / Time per Token):** Measures the actual time taken to generate output, reflecting computational efficiency.
2.  **Peak GPU Memory Utilization:** Measures how much memory is actively used during the forward pass, which directly assesses whether the model fits and how much headroom is left for the KV cache.

**Note on Performance:** Do not claim that Q4 is always faster. While smaller file size (Q4) reduces loading time, the actual computational speed depends heavily on the specific hardware architecture, kernel optimization, and the memory bandwidth constraints during the actual matrix multiplications.

## Task 5 — user-visible latency:

**Scenario:** 2,000-token prompt, 200 generated tokens.

**Definitions:**

1.  **Time to First Token (TTFT):** The time elapsed from sending the entire prompt to the model until the very first token of the generated response is produced. This measures the initial setup and prompt processing latency.
2.  **Prompt-Evaluation Throughput:** The rate at which the model processes the input prompt and prepares the initial state for generation (often measured in tokens/second or time per prompt evaluation).
3.  **Decode Throughput:** The rate at which the model generates the subsequent output tokens (measured in tokens/second, e.g., $\text{tok/s}$). This is the primary measure of generation speed.
4.  **Total Wall-Clock Time:** The total elapsed time from the moment the prompt is sent until the final generated token is received.

**Symbolic Equation for Total Time:**

$$\text{Total Time} = \text{TTFT} + \left( \frac{\text{Generated Tokens}}{\text{Decode Throughput}} \right)$$

*Note: This equation assumes that the TTFT is the initial setup time and the remainder is dominated by the sustained generation time.*

**Example where Optimizing Prompt Processing Barely Changes User Experience:**

**Scenario:** Prompt processing is optimized (e.g., using a more efficient prompt encoding method or batching the prompt processing), resulting in a $5\%$ reduction in the Prompt-Evaluation Throughput (e.g., from $X$ to $0.95X$).

**Outcome:** If the TTFT is already very short (e.g., $100\text{ms}$) and the subsequent generation time (Decode Throughput) is significantly longer (e.g., $10$ seconds), the $5\%$ change in the initial prompt processing time will be negligible ($\approx 0.5\text{ms}$). The user perceives the experience as unchanged, as the bottleneck shifts entirely to the generation phase.
