### Explanation of Naive Substring Matching Issues

Naive substring matching (e.g., searching for `event` anywhere in the line or checking if `tps` exists in the string) is prone to false positives and parsing errors:

1.  **Wrong Event Detection**: A line like `event=decode tps=100 extra=stuff` is fine, but `event=decode tps=100 event=other` might be misinterpreted if we just search for `event=`. If we split by `=`, we need to ensure we don't double-count keys. A naive check might miss the duplicate key requirement or fail to detect that `event` appeared twice.
2.  **Malformed Duplicates**: The requirement explicitly states: "Treat a duplicate `tps` key with the same value as malformed too." Naive substring search might extract the first occurrence and ignore the rest, failing the "duplicate key" check entirely.
3.  **Non-Finite/Zero/Negative**: Simple string parsing (e.g., `float(token)`) might work, but checking for `nan` or `inf` requires importing `math`. A regex might not catch `nan` or `inf` correctly without careful pattern matching.
4.  **Whitespace Handling**: Naive splitting by `=` inside a line that has multiple `=` signs (due to duplicate keys) would break if we don't track keys properly.

### Empty-Result Policy
The function returns `None` for `min_tps`, `max_tps`, and `avg_tps` when `count` is 0. This avoids division by zero and provides a clear signal that no valid data was found.

### Why O(1) Extra Space?
The algorithm iterates through `lines` once. For each line, it maintains a set of keys seen (`keys_seen`) to detect duplicates and extract values. However, since we need to return global aggregates (min, max, sum, count), we store these 4 variables (`min_tps`, `max_tps`, `sum_tps`, `count`) which is constant space regardless of input size. We do **not** store the list of valid `tps` values. We compute the minimum on the fly when a new valid `tps` is found, the maximum on the fly, and the sum is accumulated. This satisfies the O(1) extra space constraint relative to the input size.

from math import isnan, isinf
