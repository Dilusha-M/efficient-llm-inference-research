### Task 3 — Robust Aggregation
**Goal:** Validate records, handle failures, and compute median without treating failures as zero.

**Pseudocode:**
```python
def robust_aggregate_run(results):
    # 1. Validation Logic
    valid_runs = [r for r in results if r['status'] == 'success']
    failed_runs = [r for r in results if r['status'] == 'failure']
    
    # 2. Compute Median
    # If fewer than 2 successful runs exist (len(valid_runs) < 2), median is undefined.
    if len(valid_runs) < 2:
        return {
            "median": "Cannot compute median (less than 2 successful runs)",
            "failed_runs": failed_runs,
            "summary": {
                "total": len(results),
                "successful": len(valid_runs),
                "failed": len(failed_runs)
            }
        }
    
    # Sort successful runs to compute median
    sorted_valid = sorted(valid_runs, key=lambda x: x.get('decode_time', 0))
    median = sorted_valid[len(sorted_valid) // 2]
    
    # 3. Output
    return {
        "results": results,
        "median": {
            "value": float(median.get('decode_time', 0)), # Handle potential nulls
            "status": "success"
        },
        "details": {
            "failed_runs": failed_runs,
            "reason": f"{len(failed_runs)} failed runs were processed"
        }
    }
```

**Handling Out-of-Memory (OOM) Warning:**
*   **Action:** If the last run logged an OOM warning, the record remains in the `failed_runs` list but is **not** treated as a zero success.
*   **Reporting:** If fewer than two successful runs exist (e.g., 0 or 1 successful run), the function must explicitly state that the **median is undefined** or "not applicable," as there is no central point of truth to report a median for.

### Task 5 — User-Visible Latency
**Definitions:**
*   **Time to First Token (TTFT):** Time from system time to the moment the first token is generated.
*   **Prompt-Evaluation Throughput:** Tokens generated per second before the first token.
*   **Decode Throughput:** Tokens generated per second during the generation phase (after the first token).
*   **Total Wall-Clock Time:** Sum of TTFT, prompt-evaluation throughput, and decode throughput.

**Symbolic Equation:**
$$ \text{Total Wall-Clock Time} = \text{TTFT} + \text{Prompt-Throughput} \times \text{Tokens}_{prompt} + \text{Decode-Throughput} \times \text{Tokens}_{gen} $$

**Example of Optimizing Prompt Processing:**
If the **prompt-evaluation throughput** is optimized (e.g., by reducing the prompt length to fit the 512-token limit), the **Total Wall-Clock Time** remains essentially unchanged. The user's experience is almost entirely determined by the **decode throughput** (how fast the model generates tokens). Therefore, optimizing prompt processing changes the latency profile only slightly, if at all. The latency experienced by the user is determined by the **decode throughput** (tokens/sec), not the prompt processing time.
