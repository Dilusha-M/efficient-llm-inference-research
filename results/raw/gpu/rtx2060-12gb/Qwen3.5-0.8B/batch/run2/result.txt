### Task 3 — Robust Aggregation
**Pseudocode for Validation**
```python
def robust_aggregate_runs(runs):
    # 1. Validate all records exist
    records = []
    for run_id, speed in runs:
        if type(speed) is int:
            speed = speed
        records.append((run_id, speed))

    # 2. Filter out failed runs (e.g., out-of-memory, timeout)
    successful_runs = [r for r in records if r[1] != -1]

    # 3. Compute Median of successful runs
    if len(successful_runs) < 2:
        # Report result: 'No valid runs found'
        return {'median': 'N/A', 'status': 'No data'}, None

    sorted_speeds = sorted(successful_runs, key=lambda x: x[1])
    median_speed = sorted_speeds[len(sorted_speeds) // 2]
    
    # 4. Report result
    return {
        'successful_runs': len(successful_runs),
        'median_speed': median_speed,
        'failed_runs_count': len(successful_runs) - len(sorted_speeds),
        'status': 'Valid median computed'
    }
```
*   **Handling Fewer than Two Runs:** The function explicitly returns `{'median': 'N/A'}` and sets a status to 'No data' if the count is less than 2, preventing the system from silently treating the failure as zero.
*   **Handling Out-of-Memory Warning:** The `if type(speed) is int: speed = speed` step explicitly handles the numeric output, ignoring warnings and treating the failed run as a distinct failure rather than an invalid entry.

### Task 5 — User-Visible Latency
**Definitions and Equations**
*   **Time to First Token (t1):** The time elapsed from the start of the prompt generation to the first character being outputted.
*   **Prompt-Evaluation Throughput:** The average number of tokens generated per second (tokens/s) required to reach a specific latency (e.g., 10s). It is a function of the model's parameter count and the latency target.
*   **Decode Throughput:** The average number of tokens generated per second during the actual decoding phase (excluding the prompt processing). It is the raw decoding rate.
*   **Total Wall-Clock Time (t_total):** The sum of the three phases.
    *   **Symbolic Equation:**
        $$ t_{total} = t_1 + t_{prompt} + t_{decode} $$
        Where $t_{prompt}$ is the time spent processing the 2,000-token prompt and $t_{decode}$ is the time spent generating the 200 tokens.
        $$ t_{prompt} = \frac{2000}{\text{prompt\_rate}} $$
        $$ t_{decode} = \frac{200}{\text{decode\_rate}} $$
        $$ t_{total} = t_1 + \frac{2000}{\text{prompt\_rate}} + \frac{200}{\text{decode\_rate}} $$
*   **Example of Optimizing Prompt Processing:**
    *   If the **prompt rate** is optimized (e.g., by using a faster tokenizer or a model with a faster encoder), the term $t_{prompt} = \frac{2000}{\text{prompt\_rate}}$ decreases.
    *   Since the user sees the total time as $t_{total}$, optimizing the prompt processing (increasing prompt rate) **only** reduces the total time. The user's experience (latency) may or may not change, depending on how much the prompt processing time contributes to the total latency. If the prompt processing is the bottleneck, optimizing it will reduce latency; if the decoding is the bottleneck, optimizing the prompt will have a negligible effect.
