```python
import math
from typing import Dict, Any, Iterator

def summarize_decode_speeds(lines: Iterator[str]) -> Dict[str, Any]:
    """
    Summarizes decode speeds from a stream of log lines.
    
    A record is valid only if:
    1. The line contains 'event=decode'.
    2. The line contains a 'tps=<value>' field where <value> is a finite, 
       strictly positive float.
    3. If 'tps' appears multiple times, it is treated as malformed (ignore line).
    
    Args:
        lines: An iterable of strings. Non-string items are ignored.
        
    Returns:
        A dictionary with keys: 'count', 'min_tps', 'max_tps', 'avg_tps'.
        If no valid records exist, numeric stats are None.
    """
    valid_count = 0
    min_tps = None
    max_tps = None
    sum_tps = 0.0
    
    for raw_line in lines:
        # Skip non-string items gracefully
        if not isinstance(raw_line, str):
            continue
            
        # Split on whitespace to get tokens
        tokens = raw_line.split()
        
        # We need to track if we've seen 'event' and 'tps' keys and their values
        # to handle duplicates and order independence (though logs are usually sequential,
        # strict parsing requires checking the set of key-value pairs).
        
        event_val = None
        tps_val = None
        has_tps = False
        
        for token in tokens:
            # Basic heuristic: key=value where key is alphabetic
            if '=' not in token:
                continue
                
            eq_idx = token.index('=')
            key = token[:eq_idx]
            val_str = token[eq_idx+1:]
            
            # Check for event=decode
            if key == 'event':
                if event_val is not None:
                    # Duplicate 'event' key: malformed record
                    break
                event_val = val_str
                
            # Check for tps=<value>
            elif key == 'tps':
                has_tps = True
                # If we already saw tps, this is a duplicate tps key -> malformed
                if tps_val is not None:
                    break
                
                # Parse the value
                try:
                    val_float = float(val_str)
                except ValueError:
                    # Malformed float (e.g., "abc", "1.2.3")
                    break
                
                # Check constraints: finite, strictly positive
                if not math.isfinite(val_float):
                    # nan, inf, -inf
                    break
                if val_float <= 0:
                    # zero or negative
                    break
                
                tps_val = val_float
        
        # If we broke out of the loop due to an error, or if required fields are missing
        # or if it wasn't a decode event, skip this line.
        if event_val != 'decode' or (not has_tps or tps_val is None):
            continue
            
        # If we successfully parsed without breaking, and event is decode and tps is valid:
        # We must also ensure no other 'event' or 'tps' keys were present that caused a break.
        # The logic above handles the 'break' cases.
        
        # One edge case: What if the line has 'event=decode' and 'tps=5.0' but also 'tps=6.0'?
        # The loop would break on the second 'tps'. If it reaches here, it is valid.
        # What if it has 'tps=5.0' and 'event=other'? It would pass the tps check, 
        # but fail the event check at the end.
        
        if not has_tps or tps_val is None:
            continue
            
        # Add to statistics
        valid_count += 1
        sum_tps += tps_val
        
        if min_tps is None or tps_val < min_tps:
            min_tps = tps_val
        if max_tps is None or tps_val > max_tps:
            max_tps = tps_val
            
        # Calculate average only if we have at least one record (handled by count check later)
        # But since we update stats incrementally, we can compute avg at the end or here.
        # We will compute at the end to ensure integer division issues don't occur prematurely 
        # (though float division is standard in Py3).
        
    # Finalize results
    if valid_count == 0:
        return {
            "count": 0,
            "min_tps": None,
            "max_tps": None,
            "avg_tps": None
        }
    
    avg_tps = sum_tps / valid_count
    
    return {
        "count": valid_count,
        "min_tps": min_tps,
        "max_tps": max_tps,
        "avg_tps": round(avg_tps, 3)
    }

if __name__ == "__main__":
    # Demonstration lines covering:
    # 1. Valid record
    # 2. Another key=value field (should be ignored but line valid)
    # 3. Non-decode event
    # 4. Malformed float (NaN)
    # 5. Duplicate key (tps)
    # 6. Non-string item
    # 7. Valid record requiring rounding
    # 8. Negative tps
    
    demo_lines = [
        "event=decode tps=100.0",              # Valid: 100.0
        "timestamp=12345 event=decode tps=200.5", # Valid with extra field: 200.5
        "event=encode tps=50.0",               # Invalid: event is 'encode'
        "event=decode tps=nan",                # Invalid: nan is not finite
        "event=decode tps=inf",                # Invalid: inf is not finite
        "event=decode tps=1.5 tps=1.5",        # Invalid: duplicate tps key
        "event=decode tps=abc",                # Invalid: non-float value
        "event=decode tps=-5.0",               # Invalid: negative value
        "event=decode tps=0.0",                # Invalid: zero value
        123,                                    # Invalid type: ignored
        "event=decode tps=33.333333",          # Valid: requires rounding to 33.333
        "event=decode tps=0.0000001",          # Valid: very small positive
    ]

    result = summarize_decode_speeds(demo_lines)
    
    print("Demonstration Input Lines:")
    for i, line in enumerate(demo_lines, 1):
        print(f"  {i}: {repr(line)}")

    print(f"  count: {result['count']} (Expected: 4)")
    print(f"  min_tps: {result['min_tps']} (Expected: 0.0000001)")

    assert result['count'] == 4, "Failed: Did not correctly filter out the line with duplicate tps keys."

    assert result['min_tps'] == 0.0000001, "Failed: Did not correctly filter out nan, inf, zero, or negative values."
```

### Explanation of Design Choices

#### 1. Why Naive Substring Matching Fails
Naive substring matching (e.g., `if 'event=decode' in line and 'tps=' in line`) is insufficient for two critical reasons:
*   **Ambiguity with Duplicate Keys:** If a line contains `event=decode tps=5.0 tps=6.0`, a simple substring check returns `True`. However, the presence of two `tps` keys makes the record malformed according to the spec. We must parse the key-value structure to detect duplicates.
*   **Ambiguity with Event Names:** A line like `event=decode_timeout tps=50.0` contains the substring `event=decode`. A naive check would incorrectly classify this as a valid `event=decode` record. We must ensure the specific key token is exactly `event` with the value exactly `decode`.

#### 2. The Empty-Result Policy
The function returns `None` for `min_tps`, `max_tps`, and `avg_tps` when `count` is 0. This distinguishes between "no data to average" (where averaging would result in `0.0` or `NaN` depending on implementation) and "no valid records found." This prevents misleading statistics (e.g., an average of 0.0 implying 0 speed vs. unknown speed).

#### 3. One-Pass Algorithm and Space Complexity
*   **One-Pass:** The function iterates through `lines` exactly once. Inside the loop, tokens are processed in a single forward pass. There are no nested loops or re-scans of the input string.
*   **O(1) Extra Space:** We maintain a fixed number of variables (`valid_count`, `min_tps`, `max_tps`, `sum_tps`, and temporary token buffers). We do not store lists of valid records or build complex data structures proportional to the input size $N$. The space usage is constant relative to the number of lines.

1.  **`assert result['count'] == 4`**: This catches implementations that might simply sum all `tps` values found without checking for duplicate keys (which would likely include the second `1.5` in line 6, changing the count or sum) or implementations that fail silently on duplicate keys instead of rejecting the entire line.
2.  **`assert result['min_tps'] == 0.0000001`**: This specifically validates that the filter correctly rejects `nan`, `inf`, negative numbers, and zero. An incorrect implementation might treat `nan` as a valid number (resulting in `nan` for the min) or fail to handle the extremely small positive float correctly due to precision errors or incorrect inequality checks.
