### Technical Analysis

#### 1. KV Cache Lifecycle and Reuse
*   **Prompt Processing (Prefill):** The model processes the 2,000-token prompt in parallel. It computes the Key ($K$) and Value ($V$) vectors for every token. These are stored in the KV cache. Because the input is processed as a single block, the operation is **compute-bound** (high arithmetic intensity).
*   **Token-by-Token Decoding:** To generate the next token, the model only needs the $K$ and $V$ vectors of all *previous* tokens (the cache) and the $K$ and $V$ vectors of the *current* token. The previous vectors are **reused**, not recomputed. This operation is **memory-bandwidth bound** because the GPU must fetch the entire accumulated cache from memory to perform a single matrix-vector multiplication.

#### 2. Resource Stress and Throughput vs. Latency
*   **Prefill** stresses **Compute (TFLOPS)**: High parallelism allows for high tokens/sec (throughput) because the GPU can saturate its cores.
*   **Decoding** stresses **Memory Bandwidth (GB/s)**: Because each token is generated sequentially, the GPU waits for the KV cache to be moved from VRAM/RAM to the registers.
*   **The Disconnect:** A high prefill throughput indicates efficient parallel processing. However, interactive latency is dominated by the **Time Per Output Token (TPOT)**. If the KV cache is swapped to system RAM (PCIe bottleneck), TPOT will spike even if prefill remains fast.

#### 3. Scaling to 8,000 Tokens
*   **Prefill:** Complexity scales $O(N^2)$ in some attention mechanisms (or $O(N)$ with FlashAttention), but the primary constraint is the increased memory footprint for the activation tensor.
*   **Decode:** Complexity scales $O(N)$ linearly with context length. As context grows to 8,000, the KV cache size increases, directly reducing the **effective memory bandwidth**. The GPU spends more time moving "old" context to compute "new" tokens, leading to a linear degradation in TPOT.

#### 4. General Truths vs. Implementation Dependencies
*   **General Truths:** Decoding is bandwidth-bound; Prefill is compute-bound; System RAM is significantly slower than VRAM over PCIe.
*   **Implementation Dependent:**
    *   **Paging (e.g., vLLM):** Can mitigate memory fragmentation but doesn't solve bandwidth limits.
    *   **Precision (FP16 vs. INT8/INT4):** Reduces KV cache size, potentially keeping more of it in VRAM.
    *   **Kernel Support (FlashAttention):** Optimizes prefill speed but does not fundamentally change the bandwidth bottleneck of decoding.
    *   **Offloading:** Performance depends on whether the *entire* KV cache or just *parts* of it are on the CPU.

#### 5. Proposed Measurements
To isolate the bottleneck, measure the following while keeping the model and prompt constant:
1.  **Weight Bandwidth Bottleneck:** Measure TPOT with a 1-token prompt vs. a 2,000-token prompt. If TPOT is identical, the bottleneck is the weight loading (constant).
2.  **KV-Cache Bandwidth Bottleneck:** Measure TPOT as context grows from 1k $\to$ 4k $\to$ 8k. A linear increase in TPOT indicates the KV cache size is the bandwidth bottleneck.
3.  **PCIe/CPU Bottleneck:** Compare TPOT with the KV cache entirely in VRAM vs. partially offloaded to System RAM. The delta isolates the overhead of the PCIe bus.
