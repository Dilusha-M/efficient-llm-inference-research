### Task 1 — Quantization Tradeoff

**Memory Pressure Analysis:**
*   **Q8_0:** This format creates **critical memory pressure**. With 5.2 GB free and an 8.0 GB file, the weights exceed available VRAM. This necessitates "offloading," where some layers reside in system RAM. This will significantly increase latency due to PCIe bus bottlenecks.
*   **Q4_K_M:** This format creates **moderate memory pressure**. With 4.8 GB of weights and 5.2 GB free, the weights fit into VRAM, but there is very little headroom (only 0.4 GB) for the KV cache or activation tensors.

**Why File Size $\neq$ Runtime Memory:**
File size only represents the static weight footprint. Runtime memory includes:
1.  **KV Cache:** Memory allocated to store "keys" and "values" for every token in the context window; this grows with sequence length.
2.  **Activation Tensors:** Temporary memory used during the forward pass of the current token.
3.  **CUDA Context/Overhead:** The driver and library (e.g., CUDA) require a baseline overhead (often 0.5–1.5 GB) before any weights are loaded.

**Required Measurements:**
1.  **Perplexity/Loss:** To quantify the "quality" degradation of Q4_K_M compared to Q8_0 on a specific validation set.
2.  **Tokens Per Second (TPS) at specific context lengths:** To quantify the "performance" difference, as Q8_0 might be faster if the KV cache is small enough to fit in VRAM, or significantly slower if it triggers system RAM swapping.

### Task 2 — Conservative Launch Decision

**Assumptions:**
*   The 5.0 GB weight figure is the "static" size.
*   The KV cache size is dynamic and depends on the `n_ctx` (context size) and `batch_size`.

**Procedure:**
1.  **Initial Configuration (Safe Baseline):**
    *   **Offload:** Attempt to offload all layers to GPU (`n_gpu_layers = -1`).
    *   **Context:** Start with a small, conservative context (e.g., 512 tokens) to ensure the KV cache fits in the remaining ~1.2 GB of VRAM (minus CUDA overhead).
2.  **Telemetry to Record:**
    *   Peak VRAM usage during the prompt evaluation phase.
    *   Peak VRAM usage during the generation phase.
    *   Time to First Token (TTFT) and Tokens Per Second (TPS).
3.  **Iterative Scaling:**
    *   If the run succeeds, increase `n_ctx` in increments of 512 until a "CUDA Out of Memory" error occurs.
    *   If a crash occurs at a specific `n_ctx`, set the operational limit to the previous successful value.
    *   If all layers cannot fit with a 512 context, reduce `n_gpu_layers` until the model fits with the desired context.

**Unsafe/Misleading Success:**
*   **Success:** A run that completes but shows "System Memory Swap" usage or "Virtual Memory" errors (meaning the model is spilling to disk/slow RAM).
*   **Misleading:** A run that succeeds with a very small `n_ctx` but fails to handle the 2,000-token prompt requirement.

### Task 3 — Robust Aggregation

**Pseudocode:**
```python
# Input: [42.0, 41.5, 8.0] (where 8.0 is flagged as OOM)
# Data structure: List of objects {value: float, status: str}

def aggregate_results(results):
    valid_speeds = []
    failed_runs = []

    for run in results:
        if run.status == "OOM":
            failed_runs.append(run.value)
        else:
            valid_speeds.append(run.value)

    if len(valid_speeds) < 2:
        return {
            "median": "Insufficient data",
            "valid_count": len(valid_speeds),
            "failures": failed_runs
        }

    valid_speeds.sort()
    mid = len(valid_speeds) // 2
    median = valid_speeds[mid] if len(valid_speeds) % 2 != 0 else (valid_speeds[mid-1] + valid_speeds[mid]) / 2
    
    return {
        "median": median,
        "valid_count": len(valid_speeds),
        "failures": failed_runs
    }
```

### Task 5 — User-Visible Latency

**Definitions:**
*   **Time to First Token (TTFT):** The duration from the user hitting "Enter" to the appearance of the first character.
*   **Prompt-Evaluation Throughput:** The speed (tok/s) at which the model processes the 2,000-token input.
*   **Decode Throughput:** The speed (tok/s) at which the model generates the 200 new tokens.
*   **Total Wall-Clock Time:** The sum of the time taken to process the prompt and the time taken to generate all tokens.

**Symbolic Equation:**
$T_{total} = \frac{Tokens_{prompt}}{Throughput_{prompt}} + \frac{Tokens_{gen}}{Throughput_{decode}}$

**Example of Negligible Optimization:**
If a user provides a 2,000-token prompt and the model generates 200 tokens, and the system optimizes prompt processing to be 2x faster (e.g., reducing prompt time from 4s to 2s), but the generation phase takes 10s, the user's total experience only improves from 14s to 12s. The perceived "slowness" is dominated by the generation phase.
