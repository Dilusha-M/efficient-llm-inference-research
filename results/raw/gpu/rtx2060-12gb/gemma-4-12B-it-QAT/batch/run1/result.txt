### Task 1 — Quantization Tradeoff

**Memory Pressure Analysis:**
*   **Q8_0 (8.0 GB):** This format creates **high memory pressure/failure**. Since the file size exceeds the 5.2 GB of free VRAM, the system must either offload layers to system RAM (drastically slowing inference) or fail to load entirely if the driver/framework does not allow over-subscription.
*   **Q4_K_M (4.8 GB):** This format creates **low memory pressure**. It fits within the 5.2 GB free VRAM, allowing for the entire model to reside on the GPU, which is necessary for high-speed inference.

**Why File Size $\neq$ Runtime Memory:**
File size only accounts for the weights. Runtime memory includes:
1.  **KV Cache:** Memory allocated to store the "attention" of the current conversation, which grows with sequence length.
2.  **Activation Buffers:** Temporary memory used during the forward pass.
3.  **Context Overhead:** Framework-specific overhead (e.g., CUDA kernels, workspace memory).
4.  **System Overhead:** VRAM reserved by the OS or display drivers.

**Required Measurements:**
1.  **Perplexity/Loss:** To quantify the "quality" cost of moving from 8-bit to 4-bit weights.
2.  **Tokens per Second (TPS):** To quantify the "performance" gain of the smaller footprint on the specific hardware.

### Task 2 — Conservative Launch Decision

**Conservative Procedure:**
1.  **Initial Configuration:** Start with `n_gpu_layers` set to a value that leaves ~1.5 GB of VRAM free (e.g., offload ~70-80% of layers) to account for the KV cache.
2.  **Context Scaling:** Set `n_ctx` to 1024 (half the prompt length) to establish a baseline.
3.  **Iterative Expansion:** Increase `n_gpu_layers` in increments of 5 until VRAM usage reaches 90% capacity. Then, increase `n_ctx` until a crash or "Out of Memory" (OOM) occurs.

**Telemetry to Record:**
*   **VRAM Usage:** Peak memory reached during the prompt evaluation phase vs. the generation phase.
*   **Prompt Evaluation Speed:** Tokens/sec during the initial 2,000-token processing.
*   **Generation Speed:** Tokens/sec during the 512-token output.

**Unsafe/Misleading Success:**
*   **Success:** A run that completes the 2,000-token prompt but crashes at token 10 of the generation (indicates KV cache overflow).
*   **Success:** A run that completes but triggers "System Memory Fallback" (the GPU is full, and it is using slow RAM to finish the task).

### Task 5 — User-Visible Latency

**Definitions:**
*   **Time to First Token (TTFT):** The duration from "Enter" to the first character appearing.
*   **Prompt-Evaluation Throughput:** Tokens processed per second during the initial 2,000-token "pre-fill" phase.
*   **Decode Throughput:** Tokens generated per second during the 200-token "generation" phase.
*   **Total Wall-Clock Time:** The sum of TTFT and the total time to generate all tokens.

**Symbolic Equation:**
$$T_{total} = \frac{Tokens_{prompt}}{Throughput_{prompt}} + \frac{Tokens_{gen}}{Throughput_{gen}}$$

**Example of Negligible Optimization:**
If a prompt is 2,000 tokens and the system takes 10 seconds to process it, optimizing the prompt-evaluation throughput to be 20% faster only saves 2 seconds. If the user is waiting for a long generation (e.g., 50 seconds), a 2-second saving is often imperceptible to the human experience.
