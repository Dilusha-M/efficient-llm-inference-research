### Task 1 — Quantization Tradeoff

**Memory Pressure Analysis**
*   **Q8_0 (8.0 GB):** This format creates **critical/excessive memory pressure**. Since the file size (8.0 GB) exceeds the available GPU memory (5.2 GB), the system must either offload layers to system RAM (causing massive PCIe bottlenecking) or fail to load.
*   **Q4_K_M (4.8 GB):** This format creates **moderate memory pressure**. It fits within the 5.2 GB free GPU space, leaving approximately 400 MB for the KV cache and activation buffers.

**Why File Size $\neq$ Runtime Memory Estimate**
File size only represents the static weights on disk. Total runtime memory (VRAM) is a function of:
1.  **Weights:** The quantized model parameters.
2.  **KV Cache:** Memory required to store the Key/Value tensors for context/attention.
3.  **Activation Buffers:** Temporary workspace required during the forward pass.
4.  **Overhead:** CUDA/Vulkan context allocation and fragmentation.

**Required Measurements for Comparison**
To declare a "better" format, one must measure:
1.  **Perplexity (Quality):** A measure of how much information/accuracy is lost due to quantization error.
2.  **Tokens per Second (Performance):** Specifically, the *decode throughput* at a specific context length.

### Task 2 — Conservative Launch Decision

**Assumptions**
*   The 5.0 GB weight figure does *not* include the KV cache.
*   The goal is to maximize GPU utilization without triggering system swap or OOM.

**Conservative Procedure**
1.  **Baseline (First Try):** Start with a minimal number of GPU layers (`--n-gpu-layers`) such that `Weight_Size + Estimated_KV_Cache < 5.2 GB`. Given the tight margin (5.2 GB limit - 5.0 GB weights = 200 MB remaining), start with very low layer offloading to ensure the KV cache fits entirely in VRAM.
2.  **Incremental Scaling:** Gradually increase the number of offloaded layers. For each increment, test the maximum context window allowed by the remaining VRAM.
3.  **Telemetry to Record:** 
    *   Peak VRAM usage (via `nvidia-smi` or similar).
    *   System RAM usage (to detect unintended swapping).
    *   Tokens per second (to find the "cliff" where PCIe overhead outweighs GPU compute).
4.  **Unsafe/Misleading Success:** 
    *   **Unsafe:** A run that completes but triggers "System Swap" or uses 99% of VRAM, as this will crash if the context window expands or the OS requests memory.
    *   **Misleading:** A run that shows high speed because the prompt is short, but crashes during the generation phase when the KV cache grows.

### Task 3 — Robust Aggregation

**Pseudocode**
```text
function compute_median_speed(records):
    valid_speeds = []
    failed_count = 0

    for record in records:
        if record.has_error or record.status == "OOM":
            failed_count += 1
        else:
            valid_speeds.append(record.speed)

    print("Status: " + failed_count + " runs failed/OOM")

    if length(valid_speeds) < 2:
        return "Insufficient data: " + length(valid_speeds) + " successful run(s)"
    
    sort(valid_speeds)
    mid = length(valid_speeds) / 2
    if length(valid_speeds) % 2 == 0:
        return (valid_speeds[mid - 1] + valid_speeds[mid]) / 2
    else:
        return valid_speeds[floor(mid)]
```

**Reporting Strategy**
If fewer than two runs succeed, do not report a median. Report the count of successful runs and explicitly state: *"Insufficient successful samples to calculate a reliable median."*

### Task 5 — User-Visible Latency

**Definitions**
*   **Time to First Token (TTFT):** The latency between sending the prompt and receiving the very first generated token.
*   **Prompt-Evaluation Throughput:** The speed at which the model processes the input tokens (prefill phase), measured in tokens/sec.
*   **Decode Throughput:** The speed at which the model generates new tokens one-by-one (autoregressive phase), measured in tokens/sec.
*   **Total Wall-Clock Time:** The elapsed time from the start of the request to the receipt of the final token.

**Symbolic Equation**
$$T_{total} = T_{prefill} + (N_{gen} \times T_{decode\_step})$$
*(Where $N_{gen}$ is the number of generated tokens and $T_{decode\_step}$ is the latency per token during decoding.)*

**Example of Diminishing Returns**
If a user is generating a very long document (e.g., 2,000 tokens) and the prompt is short (e.g., 10 tokens), optimizing the **prompt-evaluation throughput** will have a negligible impact on the total wall-clock time, as the vast majority of the time is spent in the **decode phase**.
