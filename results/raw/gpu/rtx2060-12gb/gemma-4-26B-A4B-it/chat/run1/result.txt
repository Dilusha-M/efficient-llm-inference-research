### Analysis of System Bottlenecks in LLM Inference

#### 1. KV Cache Lifecycle
*   **Prefill (Prompt Processing):** The model processes the $N$ input tokens in parallel. For each layer, the attention mechanism computes the $K$ and $V$ tensors for all $N$ tokens. These are written to the KV cache. This is a **compute-bound** phase where the input sequence is processed as a single large matrix multiplication.
*   **Decoding (Token Generation):** For each new token $i$, the model recomputes the $Q$ vector for the single new token. To compute attention, it must fetch the **entire existing KV cache** (tokens $0$ to $i-1$) from memory. The new $K_i$ and $V_i$ are appended to the cache. This is a **memory-bandwidth bound** phase because the ratio of arithmetic operations to memory access (arithmetic intensity) is extremely low.

#### 2. Resource Stress and Throughput vs. Latency
*   **Prompt Processing (Prefill):** Stresses **Compute (FLOPS)**. High throughput (tokens/s) is achieved by saturating Tensor Cores with large matrix-matrix multiplications (GEMM).
*   **Decoding:** Stresses **Memory Bandwidth (GB/s)**. Since we only process one token at a time, we perform matrix-vector multiplications (GEMV). The bottleneck is the time taken to move model weights and the growing KV cache from VRAM to the compute units. 
*   **The Disconnect:** High prompt throughput indicates efficient utilization of compute cores, but it provides no guarantee of low decoding latency, which is governed by the speed of memory bus transfers.

#### 3. Scaling Context (2k $\to$ 8k tokens)
*   **Prefill:** Increases linearly in compute requirement ($O(N^2)$ for attention, though often $O(N)$ for modern kernels like FlashAttention) and memory footprint.
*   **Decoding:** The bottleneck shifts more heavily toward **memory bandwidth**. As the KV cache grows, the amount of data that must be read from VRAM (or system RAM) to generate a *single* token increases linearly. If the cache spills to system RAM, latency spikes due to the PCIe bus bottleneck and higher latency of DDR vs. GDDR.

#### 4. General Truths vs. Implementation Dependencies
*   **Generally True:** Decoding is memory-bandwidth bound; increasing context increases KV cache size; offloading to CPU increases latency.
*   **Implementation Dependent:**
    *   **Cache Precision:** Using FP16 vs. INT8/FP8 halves the bandwidth requirement for the KV cache.
    *   **Paging/Management:** PagedAttention (e.g., vLLM) reduces fragmentation, affecting how much "effective" memory is available before offloading.
    *   **Offload Strategy:** Whether the system offloads only the cache or also part of the weights determines if the bottleneck is PCIe bandwidth or CPU memory bandwidth.

#### 5. Proposed Measurements
To isolate the bottleneck, perform these controlled experiments:
1.  **Weight-only Bandwidth Test:** Measure decoding latency with a very small context (e.g., 10 tokens) vs. a large context (e.g., 2000 tokens). If latency is nearly identical, the bottleneck is **Model Weight Bandwidth**.
2.  **KV-Cache Traffic Test:** Measure latency as a function of context length $N$ while keeping the model small. If latency scales linearly with $N$, the bottleneck is **KV-Cache Memory Bandwidth**.
3.  **Bus Transfer Test:** Compare latency with the KV cache entirely on GPU vs. the "offload" configuration. A massive jump indicates the bottleneck is **PCIe/CPU-GPU Transfer Bandwidth**.

#### Numerical Example
*Assumptions: 7B model (FP16 $\approx$ 14GB weights, but here we assume it fits in 6GB via 4-bit quantization $\approx$ 3.5GB), GPU Bandwidth = 400 GB/s, Prefill Compute = 100 TFLOPS.*

*   **Scenario A (Compute Dominated):** A 2,000 token prompt requires $2000^2 \times \text{const}$ operations. If the prompt takes 2 seconds to process, but 300 tokens take 0.5s total (1.6ms/token), the **Prefill** dominates total time.
*   **Scenario B (Bandwidth Dominated):** The prompt takes 0.5s. However, if the KV cache for 2,000 tokens is 1GB and must be read for every token: $300 \text{ tokens} \times (1\text{GB} / 400\text{GB/s}) = 0.75\text{s}$. Here, **Decoding** dominates total time.
