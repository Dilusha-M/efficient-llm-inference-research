### Analysis of System Bottlenecks in LLM Inference

#### 1. KV Cache Lifecycle
*   **Prompt Processing (Prefill Phase):** The system processes the 2,000-token prompt in a single parallel pass. The attention mechanism computes the Key ($K$) and Value ($V$) vectors for all prompt tokens simultaneously. These are then written to the KV cache. This phase is **compute-bound** (matrix-matrix multiplication).
*   **Token-by-Token Decoding:** For each of the 300 new tokens, the model computes only the $K$ and $V$ vectors for the *single* newest token. To compute the attention output, the system must fetch the entire historical KV cache (the 2,000+ existing tokens) from memory. This phase is **memory-bandwidth bound** (matrix-vector multiplication).
*   **Reuse vs. Recomputation:** The model reuses the stored KV cache for previous tokens to avoid $O(N^2)$ recomputation, but it must "read" that cache for every single new token generated.

#### 2. Resource Stress and Throughput vs. Latency
*   **Prefill (High Throughput):** High arithmetic intensity ($FLOPs/Byte$) allows the GPU to saturate its Tensor Cores. High prompt tok/s indicates efficient use of compute units.
*   **Decoding (High Latency):** Low arithmetic intensity. The GPU spends most cycles waiting for memory controllers to fetch the KV cache.
*   **The Disconnect:** High prompt throughput is a measure of **parallelism efficiency**, while interactive latency is a measure of **memory latency and bandwidth**. A system can be a "supercomputer" at prefill but a "bottlenecked serial processor" during decoding.

#### 3. Scaling Context (2,000 $\to$ 8,000 tokens)
*   **Prefill Behavior:** Complexity scales quadratically $O(N^2)$ in compute, but for a 7B model, the prefill time will increase, though it remains relatively efficient due to parallelism.
*   **Decode Behavior:** Complexity scales linearly $O(N)$ in memory traffic. As context grows, the amount of data moved per token increases.
*   **Memory Bandwidth Role:** At 8,000 tokens, the KV cache may exceed 6 GB. If offloaded to system RAM, the bottleneck shifts from GPU VRAM bandwidth (~hundreds of GB/s) to PCIe/System RAM bandwidth (~tens of GB/s), causing a massive "latency cliff."

#### 4. General Truths vs. Implementation Dependencies
*   **Generally True:** Decoding is memory-bandwidth bound; prefill is compute-bound; increasing context increases per-token decoding latency.
*   **Implementation Dependent:**
    *   **Cache Precision:** Using FP16 vs. INT8/FP8 doubles/quarters the memory traffic and capacity.
    *   **GPU Offload/Paging:** Whether the system uses unified memory (paging) or manual offloading determines if the bottleneck is PCIe latency or bandwidth.
    *   **Kernel Support:** Techniques like *FlashAttention* or *PagedAttention* change how much memory is wasted and how efficiently the cache is accessed.

#### 5. Proposed Controlled Measurements
To isolate the bottleneck, perform these three tests:
1.  **Weight vs. KV Traffic:** Compare time-per-token for a 1-token prompt vs. a 2,000-token prompt. If latency scales linearly with prompt length, the bottleneck is **KV-cache bandwidth**. If latency is constant regardless of prompt length, the bottleneck is **weight bandwidth**.
2.  **PCIe/Bus Bottleneck:** Compare decoding latency with the KV cache fully in VRAM vs. partially in System RAM. A disproportionate jump suggests **CPU-GPU transfer (PCIe) bandwidth/latency**.
3.  **Compute Saturation:** Measure the GPU Utilization (%) during prefill vs. decode. Low utilization during slow decoding confirms a **memory-bound** state.

#### Numerical Example (Assumptions: 7B model, 16-bit KV cache, 100 GB/s VRAM, 30 TFLOPS effective compute)
*   **Scenario A (Compute Dominated - Prefill):** Processing 2,000 tokens requires $\approx 140$ TFLOPs. At 30 TFLOPS, time $\approx \mathbf{4.6s}$.
*   **Scenario B (Bandwidth Dominated - Decode):** Generating 300 tokens where each token requires reading 2,000 tokens of KV cache ($\approx 56$ MB per token). At 100 GB/s, time $\approx 56\text{MB} / 100\text{GB/s} \times 300 \approx \mathbf{0.16s}$ (total). 
*   *Note:* If the KV cache is moved to system RAM (e.g., 20 GB/s), the decode time jumps to $\mathbf{0.84s}$, a $5\times$ increase in latency.
