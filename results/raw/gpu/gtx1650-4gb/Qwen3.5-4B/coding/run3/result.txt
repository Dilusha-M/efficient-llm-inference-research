### Explanation of Naive Substring Matching Issues

Naive substring matching (e.g., `if 'event=decode' in line`) is prone to two main issues in this context:

1.  **Wrong Event Acceptance**: A line like `event=decode tps=100` contains the substring `event=decode`. However, a line like `event=decode_extra tps=100` also contains `event=decode`. Simple substring checks fail to distinguish between the exact key `event=decode` and keys containing it as a prefix. Tokenization is required to ensure we are matching the exact key structure.
2.  **Malformed Duplicate Keys**: A naive parser might parse `event=decode tps=10 tps=20` and simply take the last value found or the first. The requirement states that duplicate keys with conflicting values should be treated as malformed. Tokenization allows us to detect if the `tps=` token appears more than once before deciding to ignore the entire line.

### Empty-Result Policy

The function returns `None` for `min_tps`, `max_tps`, and `avg_tps` when `count` is 0. This is consistent with statistical conventions where aggregations over empty sets are undefined. The implementation explicitly checks `if count > 0` before calculating the average and setting min/max values, ensuring robustness against empty input or input containing only invalid records.
