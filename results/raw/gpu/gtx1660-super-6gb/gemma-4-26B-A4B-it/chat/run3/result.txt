### Analysis of the Bottleneck

The system is experiencing a transition from a **compute-bound** regime during prompt processing (prefill) to a **memory-bandwidth-bound** regime during token generation (decoding), exacerbated by **PCIe bus contention** due to KV cache offloading.

#### 1. KV Cache Lifecycle
*   **Prompt Processing (Prefill):** The model processes the 2,000-token prompt in parallel. The attention mechanism computes $Q, K,$ and $V$ matrices for all tokens simultaneously. The resulting $K$ and $V$ tensors are written to the KV cache. This is a high-arithmetic-intensity operation where the cache is **populated**.
*   **Token-by-Token Decoding:** For each new token, the model computes $Q$ for only the *latest* token. To compute attention, it must retrieve the $K$ and $V$ tensors for all *previous* tokens from the cache. These previous tokens are **reused** (not recomputed), but the cache must be read from memory for every single generation step.

#### 2. Resource Stress & Throughput vs. Latency
*   **Prefill (Compute-Bound):** High parallelism allows the GPU to saturate its Tensor Cores. The bottleneck is typically **FLOPs/s**. High prompt throughput indicates efficient matrix-matrix multiplication ($GEMM$).
*   **Decoding (Memory-Bound):** Since only one token is generated at a time, the operation reduces to matrix-vector multiplication ($GEMV$). The GPU must fetch the entire model weight set *and* the entire KV cache from memory to compute a single token. The bottleneck is **Memory Bandwidth (GB/s)**.
*   **The Disconnect:** High prompt throughput (tokens/s) measures how fast the engine can "digest" a block of text, whereas interactive latency (ms/token) measures the time to fetch weights and cache for a single step.

#### 3. Scaling Context (2,000 $\to$ 8,000 tokens)
*   **Prefill:** Increases linearly in computation ($\mathcal{O}(N^2)$ for standard attention, though often $\mathcal{O}(N)$ with FlashAttention).
*   **Decoding:** The KV cache grows linearly with context length. As the cache exceeds 6 GB, it spills to system RAM. This introduces a massive bottleneck: the GPU must now pull the KV cache across the **PCIe bus** (e.g., ~16–32 GB/s) instead of local VRAM (e.g., ~300–900 GB/s). The decoding latency will increase significantly due to the lower bandwidth of the PCIe link.

#### 4. General Truths vs. Implementation Dependencies
| **Generally True** | **Implementation Dependent** |
| :--- | :--- |
| Decoding is memory-bandwidth bound. | **Precision:** FP16 vs. INT8/FP8 KV cache halves bandwidth needs. |
| Offloading to RAM increases latency. | **Paging:** PagedAttention (vLLM) vs. contiguous allocation. |
| Increasing context increases KV cache size. | **Offload Strategy:** Entire cache offload vs. layer-wise offload. |
| Prefill is more compute-intensive. | **Kernel Support:** FlashAttention vs. standard SDPA. |

#### 5. Proposed Investigations
To isolate the bottleneck, perform these controlled comparisons:
1.  **Weight vs. Cache (VRAM Limit Test):** Run a sequence where the KV cache fits entirely in VRAM. If latency is low, the bottleneck is **PCIe bandwidth**. If latency is still high, the bottleneck is **VRAM bandwidth** (weight/cache fetching).
2.  **Precision Scaling:** Switch KV cache precision (e.g., FP16 to INT8). If performance improves proportionally to the reduction in data size, the bottleneck is **Memory Bandwidth**.
3.  **Batch Size Sweep:** Increase the number of concurrent users (batch size). If throughput increases significantly, the system was **Compute-bound** (Prefill); if throughput stays flat but latency rises, it is **Memory-bound** (Decoding).

#### Numerical Example
*Assumptions: Model Weights = 14 GB (FP16), GPU Bandwidth = 400 GB/s, PCIe Bandwidth = 20 GB/s, 1 Token $\approx$ 14 GB (weights) + Cache.*

*   **Scenario A (Compute Dominated - Prefill):**
    Processing 2,000 tokens at 100 tokens/s $\approx$ **20 seconds**.
*   **Scenario B (Bandwidth Dominated - Decoding):**
    To generate 1 token, the GPU must fetch 14 GB of weights.
    Time = $14 \text{ GB} / 400 \text{ GB/s} = 0.035 \text{s}$ (35ms).
    If the cache (e.g., 2 GB) is in System RAM:
    Time = $14 \text{ GB}/400 \text{ GB/s} + 2 \text{ GB}/20 \text{ GB/s} = 0.035 + 0.1 = 0.135 \text{s}$ (135ms).
    **Result:** Even though the prefill took 20s, the "slowdown" is felt as the decoding jumps from 35ms to 135ms per token due to the PCIe bottleneck.
