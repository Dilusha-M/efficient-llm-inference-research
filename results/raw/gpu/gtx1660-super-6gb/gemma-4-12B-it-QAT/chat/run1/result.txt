### Analysis of KV Cache Dynamics and Hardware Bottlenecks

#### 1. KV Cache Lifecycle: Prefill vs. Decoding
*   **Prompt Processing (Prefill):** The system processes the 2,000-token prompt in a single forward pass (parallelizable). For each token, the model computes Query ($Q$), Key ($K$), and Value ($V$) matrices. The $K$ and $V$ vectors are stored in the KV cache. This is a **compute-bound** operation because the arithmetic intensity is high; the GPU can reuse weights across all tokens simultaneously.
*   **Token-by-Token Decoding:** To generate the next token, the model only processes the *most recent* token. It retrieves the $K$ and $V$ vectors of all preceding 2,000 tokens from the cache to perform the attention mechanism. This is a **memory-bandwidth-bound** operation; the GPU must load the entire accumulated cache from memory for every single new token generated.

#### 2. Resource Stress and Throughput Paradox
*   **Prefill:** Stresses **Compute (TFLOPS)**. High prompt throughput (tokens/sec) indicates the GPU's ability to perform large matrix multiplications efficiently.
*   **Decoding:** Stresses **Memory Bandwidth (GB/s)**. Interactive latency is dominated by the time it takes to move the KV cache from VRAM to the streaming multiprocessors. 
*   **The Paradox:** A system can have high prompt throughput because it processes many tokens in parallel, but poor interactive latency because it cannot move the sequential cache fast enough.

#### 3. Scaling to 8,000 Tokens
*   **Prefill Behavior:** Will increase linearly in time but may hit a "memory wall" where the intermediate activations for 8,000 tokens exceed the 6 GB VRAM, forcing some computation to slow down or fail.
*   **Decode Behavior:** Will increase linearly in latency. Since each new token requires a full sweep of the 8,000-token cache, the **Memory Bandwidth Utilization** becomes the primary constraint. If the cache is offloaded to System RAM (via PCIe), the bottleneck shifts from VRAM bandwidth to **PCIe bus bandwidth**, which is orders of magnitude slower.

#### 4. General Truths vs. Implementation Dependencies
*   **General Truth:** Decoding is memory-bandwidth bound; Prefill is compute-bound.
*   **Implementation Dependent:**
    *   *Cache Precision:* FP16 vs. INT8 KV cache significantly impacts the memory footprint and bandwidth requirements.
    *   *PagedAttention/FlashAttention:* These kernels can optimize memory layout and reduce overhead, potentially masking some bandwidth limitations.
    *   *Offloading Strategy:* The latency penalty of System RAM depends entirely on the PCIe version (e.g., Gen3 vs. Gen4) and the overhead of the unified memory driver or manual swapping logic.

#### 5. Proposed Investigations
To isolate the bottleneck, perform the following:
1.  **Weight vs. Cache Bottleneck:** Measure latency for a 1-token generation at 100 tokens of context vs. 2,000 tokens. If latency scales linearly with context, the bottleneck is **KV-cache bandwidth**. If it remains flat, the bottleneck is **Weight bandwidth**.
2.  **PCIe vs. VRAM Bottleneck:** Run decoding with the KV cache entirely in VRAM (small context) vs. KV cache in System RAM (large context). Compare the ratio of latency increase to context size to calculate the **effective PCIe throughput**.
3.  **Arithmetic Intensity Test:** Measure the time taken for a 1-token generation while varying the batch size. If latency stays constant as batch size increases (until memory is full), the system is **memory-bandwidth bound**.

#### Numerical Example
*Assumptions: 7B model, FP16 weights (14GB - requires heavy offloading/quantization), KV Cache = 1GB at 2,000 tokens, VRAM Bandwidth = 200 GB/s, PCIe Bandwidth = 16 GB/s.*

*   **Prefill (2,000 tokens):** High TFLOPS utilization. Time $\approx$ 2 seconds (Parallel execution).
*   **Decoding (1 token):** 
    *   *In VRAM:* $1\text{GB} / 200\text{GB/s} = 5\text{ms}$ per token.
    *   *In System RAM:* $1\text{GB} / 16\text{GB/s} = 62.5\text{ms}$ per token.
*   **Result:** While the prefill finished in 2s, the 300-token generation in System RAM would take $\approx 18.75\text{s}$, making the decoding phase the dominant user experience factor.
