### Task 1 — Quantization Tradeoff

**Memory Pressure Analysis:**
*   **Q8_0 (8.0 GB):** This format creates **critical memory pressure** (or a failure state). Since the available GPU memory is 5.2 GB and the file is 8.0 GB, the model cannot fit entirely on the GPU. It will trigger "split" execution where some layers reside in System RAM, significantly increasing latency due to PCIe bus bottlenecks.
*   **Q4_K_M (4.8 GB):** This format creates **low memory pressure**. With 5.2 GB available, the weights fit within the VRAM, leaving approximately 400 MB for the KV cache and overhead. This allows for high-speed inference entirely on the GPU.

**Why File Size $\neq$ Runtime Memory:**
File size represents only the compressed weights. Runtime memory includes:
1.  **KV Cache:** Memory allocated to store the "context" of the conversation, which grows with sequence length.
2.  **Activation Buffers:** Temporary memory used during the forward pass.
3.  **CUDA/Context Overhead:** The driver and library overhead (e.g., cuBLAS/cuDNN) that reserve memory upon initialization.

**Required Measurements:**
1.  **Perplexity/Loss:** A quantitative measure of the model's accuracy/logic at different bit-depths to determine if Q4 sacrifices too much "intelligence" for the speed gain.
2.  **Tokens Per Second (TPS):** A measure of throughput to determine if the reduction in bit-depth translates to a meaningful real-world speed increase.

### Task 2 — Conservative Launch Decision

**Procedure:**
1.  **Baseline (GPU-First):** Attempt to load the model with all layers on the GPU (`n_gpu_layers` = max) and a small context size (e.g., 512).
2.  **Telemetry:** Record `Peak VRAM Usage`, `Time to First Token (TTFT)`, and `Tokens Per Second (TPS)`.
3.  **Iterative Expansion:** If the baseline succeeds, increase the context size in increments of 512 until a `CUDA Out of Memory` error occurs or TPS drops by $>30\%$.
4.  **Offloading:** If the model fails to fit with the desired context, reduce `n_gpu_layers` one by one, moving layers to the CPU/System RAM until the context fits.

**What to try first:**
Load the model with all layers on GPU and the minimum required context to establish a "success" baseline for the weights.

**Unsafe/Misleading Successes:**
*   **Success:** A run that completes but triggers "System RAM swapping" (extremely slow).
*   **Success:** A run where the KV cache is so small the model "forgets" the prompt mid-generation.
*   **Success:** A run where the GPU is at 99% utilization but the CPU is bottlenecked, leading to "stuttering" generation.

### Task 5 — User-Visible Latency

**Definitions:**
*   **Time to First Token (TTFT):** The latency from the user hitting "Enter" to the first character appearing. Includes prompt processing.
*   **Prompt-Evaluation Throughput:** The rate at which tokens are processed during the initial "prefill" phase (tokens/sec).
*   **Decode Throughput:** The rate at which new tokens are generated during the "generation" phase (tokens/sec).
*   **Total Wall-Clock Time:** The sum of TTFT and the time taken to generate all subsequent tokens.

**Symbolic Equation:**
$$T_{total} = \frac{Tokens_{prompt}}{Throughput_{prompt}} + \frac{Tokens_{gen}}{Throughput_{decode}}$$

**Example of Minimal Impact:**
If a user provides a very short prompt (e.g., "Summarize this: [10 words]"), optimizing the prompt-evaluation throughput from 50 tok/s to 100 tok/s will result in a negligible change in user experience (e.g., saving 0.02 seconds), whereas optimizing the decode throughput for a 500-word summary would be highly noticeable.
