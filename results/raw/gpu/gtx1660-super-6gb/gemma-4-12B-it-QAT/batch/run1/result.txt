### Task 1 — Quantization Tradeoff

**Memory Pressure Analysis:**
*   **Q8_0 (8.0 GB):** This format creates **critical memory pressure** (or an out-of-memory error). Since the file size exceeds the 5.2 GB of free VRAM, the system must either offload layers to system RAM (drastically slowing performance) or fail to load the model entirely.
*   **Q4_K_M (4.8 GB):** This format creates **moderate memory pressure**. While the weights fit in VRAM, there is only 0.4 GB of headroom. This may be insufficient for the KV cache (context memory) and activation tensors depending on the sequence length, potentially triggering "swapping" or overflow.

**Why File Size $\neq$ Runtime Memory:**
File size represents only the static weights. Runtime memory includes:
1.  **KV Cache:** Dynamic memory allocated based on sequence length and batch size.
2.  **Activation Tensors:** Temporary memory used during the forward pass.
3.  **CUDA Context/Overhead:** The driver and libraries (like cuBLAS) require a baseline of VRAM even before the model loads.

**Required Measurements:**
1.  **Perplexity/Loss:** To measure the "quality" trade-off (how much accuracy is lost by moving from 8-bit to 4-bit).
2.  **Tokens per Second (TPS):** To measure the "performance" trade-off (latency/throughput) under the specific hardware constraints.

### Task 2 — Conservative Launch Decision

**Procedure:**
1.  **Initial Attempt (Safe Baseline):** Load the model with 0 layers on GPU (CPU only) to establish a baseline, then attempt to offload layers sequentially (e.g., 10, 20, 30...) until VRAM usage reaches ~85% of the 6 GB limit.
2.  **Context Selection:** Start with a small context window (e.g., 512 tokens). If stable, increment by 512 until a crash or "Slowdown" (e.g., >50% drop in TPS) occurs.
3.  **Telemetry to Record:**
    *   `VRAM_Used` (Total during inference).
    *   `TPS` (Tokens per second) during the generation phase.
    *   `Prompt_Processing_Time` (Time to first token).
    *   `Max_Context_Reached` (The highest token count before a crash).

**Unsafe/Misleading Successes:**
*   **System Swap:** If `VRAM_Used` exceeds 6 GB and the OS begins using disk swap, the "success" is misleading as it masks a performance collapse.
*   **OOM-on-Generation:** If the model starts generating but crashes halfway through because the KV cache grew too large, the initial "success" was unsafe.

### Task 5 — User-Visible Latency

**Definitions:**
*   **Time to First Token (TTFT):** The latency from sending the prompt to receiving the first generated word.
*   **Prompt-Evaluation Throughput:** The speed at which the model processes the input tokens (tokens/sec).
*   **Decode Throughput:** The speed at which the model generates new tokens (tokens/sec).
*   **Total Wall-Clock Time:** The total time elapsed from the start of the request to the end of the final generated token.

**Symbolic Equation:**
$$T_{total} = \frac{Tokens_{prompt}}{Throughput_{prompt}} + \frac{Tokens_{gen}}{Throughput_{decode}}$$

**Example of Negligible Optimization:**
If a user provides a 2,000-token prompt and the model generates 200 tokens, and an optimization reduces the prompt-evaluation time from 2.0 seconds to 1.5 seconds, the user's experience is barely changed because the total time (including generation) remains dominated by the heavy inference of the 200 generated tokens.
