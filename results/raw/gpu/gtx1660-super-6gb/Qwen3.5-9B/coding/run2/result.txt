    """
    Summarize decode speeds from an iterable of log lines.

      - It contains the key 'event' with value 'decode'.
      - It contains the key 'tps' with a finite, strictly positive float value.

      - The line is treated as a sequence of whitespace-separated tokens.

        lines: An iterable of strings (non-string items are ignored).

    # Given the problem context (log lines), K is small and bounded, so this is effectively O(1) relative to the input size N.
    
    for raw in lines:
        # Ignore non-string items
        if not isinstance(raw, str):
            continue
            
        # Split on whitespace
        tokens = raw.split()
        
        # Dictionary to hold key-value pairs for this specific line to detect duplicates
        line_values = {}
        has_decode = False
        
        for token in tokens:
            if '=' not in token:
                continue
            
            # Split only on the first '=' to handle potential '=' in values (though unlikely in this format)
            key, value = token.split('=', 1)

            value = value.strip()

        line_values = {}

### Explanation of Design Decisions

1.  **Naive Substring Matching Pitfalls**:
    *   **Wrong Event**: A naive approach like `if 'decode' in line` fails because a line could contain `event=encode tps=100` which has the substring "decode" inside "encode" (if not careful) or simply because the text "decode" might appear in a comment or unrelated field. We must explicitly check `event=decode`.
    *   **Malformed Duplicates**: Naive parsing often stops at the first `tps` value. If a line is `event=decode tps=100 tps=200`, a naive reader might take `100`. Our implementation parses all tokens first. If a key repeats, we mark the line as malformed immediately, regardless of whether the second value is the same or different, satisfying the requirement that *any* duplicate makes it invalid.
    *   **Empty-Result Policy**: If no valid records are found (count is 0), returning `None` for min, max, and avg prevents division by zero errors and clearly signals the absence of data, rather than returning `0` or `0.0` which might imply a speed of zero.

2.  **One-Pass Algorithm & O(1) Space**:
    *   The function iterates through the `lines` iterable exactly once.
    *   For each line, we create a small dictionary (`line_values`) to track keys encountered *within that specific line*. The size of this dictionary is bounded by the number of tokens in a single line (a constant relative to the total input size $N$), satisfying the $O(1)$ extra space constraint relative to the input stream. We do not store the entire history of lines.

3.  **Demonstration Lines**:
    The `demo_lines` list covers all specified edge cases:
    1.  `event=decode tps=100.0`: Standard valid record.
    2.  `event=decode tps=50.0 other=ignored`: Valid record with extra irrelevant key-value pairs.
    3.  `event=encode tps=200.0`: Non-decode event (filtered out).
    4.  `event=decode tps=abc`: Malformed float (string instead of number).
    5.  `event=decode tps=nan`: Non-finite value (filtered out).
    6.  `event=decode tps=100 tps=200`: Duplicate key (filtered out).
    7.  `None`: Non-string item (ignored by `isinstance` check).
    8.  `event=decode tps=100.00001`: Valid record requiring rounding in the average calculation.

4.  **Assertions**:
    *   `assert result['count'] == expected_result['count']`: Ensures the logic for counting valid records is correct, specifically handling the exclusion of malformed entries.
    *   `assert result['avg_tps'] == expected_result['avg_tps']`: Ensures the arithmetic mean calculation and the specific rounding to three decimal places are implemented correctly.
