    Rules:
    - Ignore non-string items.
    - Split line on whitespace.

    - Require 'tps=<value>' where value is a finite, strictly positive float.

### Why Naive Substring Matching Fails

Naive substring matching (e.g., checking if `"event=decode"` appears anywhere in the line) can lead to incorrect results because:

1. **Wrong Event Detection**: A line like `"foo=bar event=decode tps=100"` would match `"event=decode"` even if the user intended a different context, and more critically, a line like `"event=decode tps=abc"` might be incorrectly accepted if only substring search is used without proper parsing.
2. **Malformed Duplicates**: Naive matching might not detect duplicate keys properly. For example, a line with two `event=` keys would be incorrectly accepted if the parser doesn't track which key was last set.
3. **Tokenization Issues**: Substring matching doesn't respect the tokenization rules (splitting on whitespace). A line like `"event=decode tps=100 extra=stuff"` would be correctly parsed by token-based approach, but naive string search might misinterpret parts of `extra=stuff` as part of `event`.

### Empty-Result Policy

If no valid decode records are found (count == 0), the function returns `None` for `min_tps`, `max_tps`, and `avg_tps`. This is important to avoid returning `0` or `0.0` which would be misleading. The policy ensures that the absence of data is explicitly represented.
