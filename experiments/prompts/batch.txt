Answer the following independent benchmark-review tasks. Keep answers clearly separated. Be explicit about assumptions, distinguish measured facts from hypotheses, and call out any case where the requested conclusion cannot be determined from the supplied data.

Task 1 — quantization tradeoff:
An 8B model has a 8.0 GB Q8_0 file and a 4.8 GB Q4_K_M file. A 6 GB GPU has 5.2 GB free before inference. Explain which memory pressure each format creates, why file size is not a complete runtime-memory estimate, and give two quality/performance measurements needed before declaring one format better. Do not claim that Q4 is always faster.

Task 2 — conservative launch decision:
A machine has 16 GB RAM, a 6 GB GPU, a 2,000-token prompt, and a 512-token generation limit. The model weights occupy 5.0 GB in the chosen quantization. Describe a conservative procedure for choosing context size and GPU layer offload in llama.cpp. Include what should be tried first, what telemetry should be recorded, and what would count as an unsafe or misleading success. Do not assume the 5.0 GB weight figure includes the KV cache.

Task 3 — robust aggregation:
Three runs report decode speeds of 42.0, 41.5, and 8.0 tok/s; the last run logged an out-of-memory warning. Write short, language-agnostic pseudocode that validates records, keeps the failed run visible, and computes the median for successful runs without silently treating the failure as zero. State how you would report the result if fewer than two runs succeed.

Task 4 — validity audit:
Identify four threats to validity in a CPU/CUDA/Vulkan comparison where the CPU uses 8 threads, CUDA offloads all layers, Vulkan offloads all layers, and each backend is run three times. For each threat, give a concrete control or disclosure. At least one threat must concern workload/output comparability, not just hardware or software.

Task 5 — user-visible latency:
For a 2,000-token prompt and 200 generated tokens, explain the difference between time to first token, prompt-evaluation throughput, decode throughput, and total wall-clock time. Give a symbolic equation for total time and one example where optimizing prompt processing barely changes the user's experience. Do not equate tok/s with latency without specifying which phase it describes.
